# 从游戏截图或录屏还原蓝图

桌面版顶部「截图 / 录屏识别」可以选择 1–16 张 PNG/JPEG/WebP、一个包含图片的 ZIP，或单个 MP4/MOV/WebM/MKV 视频。录屏会自动选择清楚、有新增覆盖且互相重叠的关键帧，再进入同一套拼接与识别流程。识别后先展示拼接图、覆盖图、设备数量和需要核对的信息；导入后可直接在画布纠正设备和线路，可以撤销。完整识别结果保留原始证据，编辑器的「保存 JSON」也会保留识别对照信息（不含图片）。

识别只在 Windows 桌面版中提供：页面和识别服务在同一个本地程序里，双击即可使用，安装、打包和排查见 [桌面版说明](../desktop/README.md)。网页版（Cloudflare Pages 等静态部署）不包含识别界面，可以用「导入 JSON」打开识别结果中的布局。

## 开发时运行

在项目根目录使用 Python 3.10 或更高版本：

```sh
python -m venv .venv
source .venv/bin/activate            # Windows：.venv\Scripts\activate
python -m pip install -r scripts/ocr/requirements.txt
```

两种方式任选其一：

- 桌面版同源服务：`pnpm build:desktop` 后运行 `python desktop/app.py --serve`，在浏览器打开 `http://127.0.0.1:47615`。
- 独立识别服务配合开发页面：`python scripts/ocr_server.py`，再用 `vite --mode desktop` 启动页面；对话框中会显示服务地址（默认 `http://127.0.0.1:8765`）。服务只监听本机回环地址，默认允许 `localhost` / `127.0.0.1` 的 5173 和 4173 端口，其他来源需要 `--allow-origin` 指定。

视频解码默认使用 PATH 中的 `ffmpeg`、`ffprobe`，找不到时使用 OpenCV 自带的 FFmpeg 解码；两者解出的原图逐像素相同。可以用环境变量 `BLUEPRINT_VIDEO_DECODER=ffmpeg|opencv` 指定，桌面版固定使用 OpenCV。图片和视频都在本机处理，不发送给云端模型。

直接识别本次截图：

```sh
python scripts/recognize_blueprint.py 蓝图截图.zip --output reports/ocr-result
python scripts/recognize_blueprint.py 蓝图截图2.zip --output reports/ocr-result-2
python scripts/recognize_blueprint.py "2026-10-06 00-33-40.mp4" --output reports/ocr-video-result
```

也可以传多张截图；若文字 OCR 无法读取尺寸，可显式指定格数：

```sh
python scripts/recognize_blueprint.py 1.png 2.png 3.png --size 33 44 --output reports/ocr-result
```

识别弹窗也提供可选的宽、高输入；留空使用自动识别。HTTP 客户端可发送 `{"files": [...], "size": [33, 44]}`，尺寸必须是两个 1–50 的整数。

视频 HTTP 接口为 `POST /api/recognize-video?name=录屏.mp4`（文件名须 URL 编码），请求类型为 `application/octet-stream`，直接发送文件字节；可附加 `width=37&height=43`。不会把整段视频转成 Base64。

上面两个接口会一直等到识别结束才返回。编辑器使用后台任务接口，可以显示进度、随时取消，关闭弹窗、切换页面或刷新后也能接着看进度：

| 接口                                 | 作用                                                                                                      |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `POST /api/jobs`                     | 请求体与 `/api/recognize` 相同；返回 202 和 `{"job": {...}}`                                              |
| `POST /api/jobs/video?name=录屏.mp4` | 请求体与 `/api/recognize-video` 相同                                                                      |
| `GET /api/jobs/{id}`                 | `status`（running / done / error / cancelled）、`stage` 阶段名、`progress` 0–1、`elapsedSeconds`、`error` |
| `GET /api/jobs/{id}/result`          | 完成后的识别结果；未完成返回 409                                                                          |
| `GET /api/jobs/latest`               | 最近一次任务的状态                                                                                        |
| `DELETE /api/jobs/{id}`              | 取消；在下一个检查点停止，并结束 ffmpeg 和并行进程                                                        |

同一时间只运行一项识别；已有任务时再提交会返回 429，响应中带有正在运行的任务。服务保留最近 3 项任务的结果 1 小时，重启服务后丢失。编辑器在浏览器本地存储中记住任务 ID，页面重新打开时自动接回。

输出包括：

| 文件                                            | 用途                                                                 |
| ----------------------------------------------- | -------------------------------------------------------------------- |
| `blueprint.json`                                | 可直接导入编辑器的 schemaVersion 2 布局                              |
| `recognition.json`                              | 布局、完整识别报告和内嵌拼接预览，供「截图识别」打开及叠加对照       |
| `mosaic.png`                                    | 在统一格网下拼接的原截图                                             |
| `coverage.png`                                  | 每个像素有多少张有效截图覆盖，0 表示未知                             |
| `coverage-review.png`                           | 按格着色的覆盖图；绿 ≥98%、黄 10%–98%、红 <10%，仅表示看到了多少画面 |
| `video-selection.json`                          | 录屏参数、候选与选中帧、真实时间点、自动选择依据                     |
| `source-map.png`                                | 拼接像素来自哪张截图                                                 |
| `registration.json`                             | 平移、网格、配准残差、遮挡区域和逐格覆盖                             |
| `tooltip-underlay.png` / `tooltip-evidence.png` | 半透明提示框残留的辅助增强图 / 弱证据位置；不替代原图或原始覆盖率    |

`reports/` 是本地生成产物，不入库。CLI 的输出目录还保留解码后的输入图和有效区域 mask，便于审计。

## 导入后对照原图修改

导入后右侧显示「识别对照」：可切换叠加原图、查看原图、查看蓝图和覆盖范围，并调整透明度；对照图不会出现在导出图片里。直接用编辑器现有工具移动、旋转、更换设备或重新画线即可，不需要逐项确认。

列表只放识别得不太确定的地方，点一下会定位、放大并高亮：

- 明显缺失的画面区域（覆盖不足不能当成空地）；
- 箭头方向接近或与相邻格不衔接的线路，相连的同类线路格合并成一处；
- 被遮挡的设备，以及和另一种设备几乎一样像（得分差 ≤ 0.005）的设备。

已由相邻设备接口或线路推断出方向的线路、外观相近的朝向候选不再列出。示例录屏的条目从 177 项减少到 24 项。

「关闭对照」去掉原图和列表，只保留布局，可撤销；「清空布局」和顶部「新建」也会一并清掉识别对照。「另存识别结果（含原图）」保存当前布局、原始布局、报告和已加载的对照图，重新打开后可以继续对照。再次打开同一识别结果会回到当前修改稿；导入另一份结果替换当前非空布局，需要在界面明确选择替换。只保存布局 JSON 后重新打开，对照图片需要另选 `mosaic.png`。

## 如何还原

单纯的文字 OCR 不包含建筑位置和线路。识别器组合了几种证据：

0. 视频先做有数量和解码时间上限的自动采样，结合滚动条位置、清晰度、提示框遮挡与新增可见面积选帧；近重复画面去重，所选画面保持重叠。选帧覆盖的是录屏中观察到的范围，最终是否完整仍以拼接覆盖图为准。
1. 先按解码像素去掉完全重复的截图，保留来源映射；RapidOCR 综合各图右侧名称、尺寸、创作者 ID 和设备数量。相同设备的数量不相加，冲突数量单列为未知。库存图标只作为匹配先验，完整素材库仍参与设备识别。
2. 自动检测预览区域、滚动条和黑色提示框。滚动条提供粗略位置，SIFT 特征匹配再确定精确位移；重叠像素和配准环路检查能排除重复产线造成的假匹配。蓝图比预览区窄时，游戏不显示该方向的滚动条，网格会延伸到两侧空白处；这时按设备和线路所在的列（或行）确定蓝图从哪一格开始，前提是蓝图两端都有内容（游戏中蓝图尺寸就是内容的外框）。
3. 从背景格线估计每格像素与格网原点，将全部截图拼入同一个坐标系。重叠区域选择更清楚的原图，不把缺失区域补成假证据。
4. 复用 `BlueprintBaker` 合成的四向设备、原始物品徽标和物流图标，在格网内匹配、去重；被提示框遮住的设备使用仍可见的边框匹配。设备数量与库存 OCR 单独对照。生产物品词典排除复用同一图标的蓝图道具，并依据原始状态素材识别未知配方角标。
5. 逐格识别传送带/管道的直线和转角模板，分离管道覆盖的底层传送带。管道也可覆盖仓库取货口。遮住的箭头可由相邻接口和线路约束推断；短的完全遮挡直线仅在两端方向一致时补齐，并在报告标为推断。
6. 对半透明提示框，屏蔽其白色文字和图标，从剩余低对比像素匹配隐藏物流节点，并为线路补充弱证据。该来源单列为 `translucent_tooltip_pixels`，不把增强图当作无遮挡原图，也不覆盖相互矛盾的直接观测。

报告中的相关度是模板相似程度，不是统计学上的正确概率。`visibleFraction`、候选方向、候选物品以及 `inferredFromConnectivity` 等字段保留直接观测与推断的区别。

## 当前支持范围

- 输入应为游戏内「蓝图预览」页面，保留右侧详情、预览滚动条和相邻截图重叠区域；同一批截图保持相同游戏缩放倍率。完整屏幕截图被等比例压缩或放大可以归一化，拼接已用第二份样例混合 1440p、1080p、720p 验证；改变游戏视角缩放不等同于缩放图片。
- 录屏保持同一张蓝图、相同游戏缩放，沿着有重叠的路径慢慢扫过四边；每到一处稍停、移开鼠标提示框能提高可见覆盖。音轨不参与识别。
- 截图顺序不影响拼接。同一行反复出现的相同设备会由滚动条和整体配准校验约束。
- 截图集合需要拍到整张蓝图的左右和上下边界，才可确定绝对格坐标；不能据仅有中间局部的截图猜测其位置。单图只有涵盖完整范围时可用。任意裁剪、批内改变游戏缩放、没有可靠重叠或缺少边缘的图会拒绝拼接。
- 同一个设备在多张截图中出现，先映射到统一格坐标再识别一次。不同位置的同形设备和重复产线全部保留；不能仅因外观相同而合并。`coverage.png` 的次数是有效图像覆盖次数，不是统计独立证据数。
- 大小最多 50×50 格、160 个节点，沿用编辑器约束。每次最多 16 张、压缩与解压数据分别最多 64 MiB；图片每张最多 2400 万像素，总共最多 1.2 亿像素。
- 录屏每次单个、不与图片混传，最多 256 MiB、180 秒、120 FPS。还受实际解码像素/帧数预算约束，高分辨率高帧率长视频可能需缩短；最多采样 360 帧，选用最多 16 帧，并遵守总像素上限。
- 截图看不到的内容不能由 OCR 证明：完全遮挡的图标、外观对称的方向、隐藏端口设置、配方状态、地下管道配对等可能需要人工核对。设备数量一致也不代表每段线路都已验证正确。
- 录屏各帧的右侧详情面板只差压缩噪声时只识别一次，复用的帧在报告中标注 `panelReadFrom`；面板文字或清单卡片有变化时仍会重新读取。截图仍按像素完全相同才复用。
- 设备模板匹配、物品徽标匹配和模板渲染在多个进程中并行，默认使用 `min(16, CPU 核数)` 个进程，可用环境变量 `BLUEPRINT_OCR_THREADS` 调整；设为 `1` 时全部串行。结果按原有顺序汇总，与串行结果相同。从其他 Python 程序调用 `recognize()` 时，主模块需要有 `if __name__ == "__main__":` 保护。
- 目前针对上述游戏预览样式实现，尚未训练成能识别任意视角的 3D 工厂截图或任意其他版本 UI 的通用模型。

本次 8 张截图自动配准的有效像素覆盖约 99.07%；左上角两个黑色提示框没有其他截图补足。要做无推断的验收，应移开鼠标提示框，补拍蓝图左上角约 7×5 格。完整审计以生成的 `recognition.json` 为准。

这组图已识别清单中的 67 台设备、11 个物流节点及 51 个物品徽标，其中一个物流节点来自半透明提示框残留。数量对应不等于所有箭头均已确认，报告仍保留局部线路与对称朝向的待核对项。

第二份 `蓝图截图2.zip` 含 4 张截图，自动识别名称「四核息壤单水右」、39×23 格，恢复 36 台设备、11 个物流节点、28 个物品徽标、4 个未知配方状态及 248 格线路，设备清单数量全部对应。有效覆盖约 99.93%。目前有 23 个线路格仍需核对，51 个线路格包含连接推断，这两组可能重叠；相邻线路出口与入口不衔接时会把两端都加入核对列表。结果和带对照图的完整报告在 `reports/ocr-result-2/`。

这段 `2026-10-06 00-33-40.mp4` 录屏约 10 秒、2560×1440。程序从 60 个候选画面自动选取 13 帧，恢复「1.4武陵城左上4」37×43 格，自动输出 55 个普通设备、26 个物流节点、40 个物品徽标和 387 格线路，有效画面覆盖约 99.89%。本机完整 CLI 耗时最初约 257 秒，并行化后约 55 秒，输出布局逐字节相同（128 核机器，默认 16 个工作进程）。6 个仓库口的取货/存货类型仍有歧义，23 个线路格待核对，29 个线路格含连接推断，两者可能重叠。补充抽查发现 `(20,17)` 应为芽针物品准入口而被归为管道层，`(20,20)` 漏了锦草物品准入口，后者朝向仍无法区分；坐标从 0 开始，证据与候选存于 `reports/ocr-video-result/manual-checks.json`。覆盖率描述看到的画面范围，不表示识别正确率。

## 验证

```sh
python -m pip install pytest
python -m pytest tests/test_ocr*.py
node tests/recognition.test.mjs
```

Python 测试检查视频抽帧预算与选帧、覆盖区域、文件/ZIP 边界、线路方向与叠层、遮挡补线条件和真实本机 HTTP 请求；前端测试检查文件限制、结果校验、显式导入、撤销、失败处理、取消和报告往返。原始截图的集成验收另由上面的 CLI 命令运行。

相关实现：`scripts/ocr/`、`scripts/ocr_server.py`、`src/ui/recognition.ts`。文字 OCR 使用 [RapidOCR](https://github.com/RapidAI/RapidOCR)，图像配准和匹配使用 [OpenCV](https://docs.opencv.org/4.x/)。
